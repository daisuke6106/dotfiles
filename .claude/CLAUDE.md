# グローバル指示

## 応答言語
- ユーザーとの対話は常に日本語で行う。
- コード自体（変数名・既存コメントなど）は無理に翻訳しない。

## git操作時の注意事項
- 破壊的な操作（`git reset --hard`、`git push --force`、`git checkout --`、`git clean -f`、`git branch -D` など）は、ユーザーが明示的に要求しない限り実行しない。
- コミットやプッシュなど、共有状態に影響する操作を行う前には必ずユーザーに確認する。
- pre-commitフックやGPG署名は `--no-verify` などでスキップしない（ユーザーが明示的に指示した場合を除く）。
- 破壊的になりうるgitコマンドを実行する前には `git status` で作業ツリーの状態を確認し、未コミットの変更があればstash等で退避してから進める。
- コミットは新規作成を基本とし、`git commit --amend` はユーザーが明示的に求めた場合のみ使用する。
- `git add -A` や `git add .` は避け、意図したファイルのみをステージする（`.env` や認証情報などの誤コミットを防ぐため）。

## ファイル操作時の注意事項
- 既存ファイルを上書き・削除する前には、その内容を確認してから作業する。見覚えのないファイルや設定は、削除・上書きする前に必ず調査する。
- ファイルを削除する必要があるが確信が持てない場合は、削除ではなく退避（リネーム・移動）を優先する。
- 既存ファイルの編集は新規作成より優先する。ユーザーが明示的に要求しない限り、新しいファイル（特にドキュメント類）は作成しない。
- 秘密情報（APIキー、認証情報、`.env` の中身など）が含まれる可能性のあるファイルを扱う際は、内容を慎重に確認し、外部に送信・記録しない。
